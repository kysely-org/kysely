# TypeORM comparison checks

Reproduce the examples in `site/docs/comparisons/kysely-vs-typeorm.mdx` using
published Kysely 0.29.8, TypeORM 1.1.2, and TypeORM 0.3.31. The runner rejects
version drift, type-checks every fixture with strict TypeScript 6 and 7 against
each TypeORM release (the `legacy` import condition selects 0.3.31), then runs
each fixture twice against a disposable PostgreSQL server, once per release.

From this directory:

```sh
npm install --ignore-scripts --legacy-peer-deps --no-audit --no-fund
COMPARISON_DATABASE_URL=postgres://user:pass@localhost:5432/db npm test
```

Each run creates its own schema and drops it afterwards; the user needs
`CREATE SCHEMA`. TypeORM's PostgreSQL `stream()` needs `pg-query-stream`, which
is installed here as a dev dependency. The standalone package keeps comparison
dependencies out of the site's runtime. `skipLibCheck` skips third-party
declaration internals; fixture expressions and inferred types are checked.
Expected Kysely errors use `@ts-expect-error`, which fails compilation if an
expected error disappears. Invalid TypeORM expressions compile without
suppression, and assertions record the PostgreSQL error code that rejects each.

These fixtures do not test transports other than node-postgres, do not measure
performance, and do not prove the absence of every possible API. Missing-method
claims also require reviewing the published declarations and official docs for
the pinned versions.
