## Flags

- **Stacks no longer uses Kysely.** [Commit dd8d299, December 16, 2025](https://github.com/stacksjs/stacks/commit/dd8d2994987bd226ef24db9fdaf5ec6b54b29948) removed `kysely` and `kysely-bun-worker` from its database package. GitHub reports no associated PR. The current [database implementation](https://github.com/stacksjs/stacks/blob/fc5d629c394284e61cb7951449b88d2706d3187d/storage/framework/core/database/src/index.ts) uses `bun-query-builder`. No current source imports or package dependencies establish Kysely usage. This predates the existing August 2026 proof link: similarly named query methods were a false positive. Removed Stacks from the active wall and deleted its unused logo and label configuration.
- **Notesnook uses a fork.** Its [core package](https://github.com/streetwriters/notesnook/blob/bf909697d8bb2979d698334374f935a0f6161669/packages/core/package.json) and query source use `@streetwriters/kysely`. This is continuing use of a Kysely fork, rather than a confirmed departure from Kysely.
- **Tunarr and Sink still use Kysely alongside Drizzle.** Their selected proof files show current Kysely queries; the presence of Drizzle alone is not evidence of a completed migration.
- **Statement-only entries remain historical evidence.** Best Western, Bold.org, Deno, Founderpath, Maersk, Open.cx, Replicas, and Sesame Care do not expose a repository through these proof links. Public statements cannot confirm their current private implementations or establish that they stopped using Kysely. The six linked GitHub comments remain available; the Deno Reddit statement remains available. The Replicas X post was inaccessible to the browser, so its link now points to the CTO’s accessible first-party migration article, dated July 28, 2026.

## Method

Downloaded each repository’s default-branch HEAD snapshot and inspected TypeScript/JavaScript source, imports, and dependency manifests. Ranked application/library source using parsed syntax: `selectFrom`, `selectNoFrom`, `insertInto`, `updateTable`, `deleteFrom`, `mergeInto`, and `replaceInto` call sites, plus SQL statement templates beginning with SELECT/WITH/INSERT/UPDATE/DELETE/REPLACE/MERGE. Excluded tests, fixtures, examples, playgrounds, scaffolding templates, documentation, generated build output, and migration files. Subqueries count as call sites; counts are an illustration of query coverage, not the number of SQL statements executed at runtime. Checked selected wrappers against their Kysely implementation; a matching method name alone is insufficient.

AWS Blocks, Depot, Evolu, MikroORM, and Tailor expose adapter/compiler/integration code without eligible application query call sites, so their existing integration or dependency evidence was retained at the latest snapshot. Evolu’s standalone SQLite SQL tag was excluded from Kysely counts. Depot retains its production-use statement as the visible link; its driver repository alone would not establish internal production use.

Permalinks use the HEAD observed during this audit. `provenAt` uses that commit’s committer date, matching the existing verifier. Published package evidence uses the latest release version and publication date. Reading an old statement does not reset its date.

## Scoring

No manual score recalculation or formula change is needed. The page computes `weight × 0.5^(min(24, floor(ageDays / 30)) / 18)` from `provenAt`: pinned code weighs 1 and statements weigh 0.6. A site build/render picks up refreshed dates. Query count is not part of the score, and “Built into” entries have no score. Keep that distinction: selecting a more illustrative source file should not reward larger codebases.

The verifier does need stricter evidence validation: its `.selectFrom()` fallback incorrectly treats compatible APIs as proof of Kysely. Repository activity also differs from last modification of the proof file; the current policy measures evidence at the pinned repository snapshot, not query-file activity.
